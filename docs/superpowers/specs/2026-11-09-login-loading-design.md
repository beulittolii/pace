# 로그인 단계별 로딩

## 승인된 목적과 흐름
로그인 중 화면이 멈춘 것처럼 보이지 않게 한다.

`로그인 클릭 → 버튼 스피너 + 로그인 중… → 인증 성공 → 기존 스켈레톤 → 데이터 준비 완료 → 실제 화면`

실패하면 로딩을 해제하고 로그인 화면에 오류를 표시하며 다시 시도할 수 있게 한다. 사용자가 이 흐름을 승인했다.

## 접근 방식
- 버튼 로딩만 사용: 인증 이후 데이터 준비 상태를 충분히 전달하지 못한다.
- 클릭 즉시 스켈레톤: 인증과 데이터 준비를 구분하지 못한다.
- **선택: 버튼 로딩 다음 기존 스켈레톤 재사용.** 승인된 단계 구분을 유지하고 새 디자인을 만들지 않는다.

## 구현 제약과 결정
- 기존 JavaScript/Firebase 구조를 유지하며 의존성을 추가하지 않는다.
- 기존 스켈레톤 HTML/CSS와 학생·관리자 변형을 재사용한다. 역할 확인 전에는 기본 변형을 사용한다(구현자 결정).
- 스켈레톤은 데이터 로딩이 끝나고 실제 화면을 렌더링한 뒤 해제한다. 인위적인 최소 대기 시간을 넣지 않는다.
- 인증 실패, 데이터 로딩 실패, 재시도와 중복 제출을 처리한다.
- 초대 코드 입력이 필요한 계정은 기존 가입 흐름을 유지하며 스켈레톤을 해제한다.
- 초기 화면, 자동 로그인, 비밀번호 표시 및 자동 로그인 설정의 기존 동작을 깨뜨리지 않는다.
- 서버 인증 방식 변경, 새 로딩 화면 디자인, 배포는 범위 밖이다.
